# poker-bot

Бот хранит игры в SQLite: `groups`, `players`, `group_players`,
`game_sessions`, `player_results`. Каждая дата в группе соответствует одной игре.

## Восстановление из Telegram

Экспортируйте нужную группу в Telegram Desktop: меню группы → «Экспорт
истории чата» → JSON → весь период. Для восстановления текстовых отчётов
Telegram API и токен бота не нужны.

Сначала выполните анализ без создания базы:

```powershell
python recover.py "путь/к/result.json"
```

Результат появится в `recovery/report.json`, `recovery/results.txt` и
`recovery/stats.txt`. Существующая `poker.db` не изменяется. Скрипт разбирает
текстовые отчёты, включая форматированные сообщения, учитывает подтверждённые
ботом отмены и устраняет одинаковые повторы. Разные отчёты за одну дату и
неразобранные строки блокируют создание базы.

Для повторного восстановления с проверенными сопоставлениями имён:

```powershell
python recover.py recovery/telegram-export/result.json --config recovery/config.json
python recover.py recovery/telegram-export/result.json --config recovery/config.json --write-db recovery/restored.db
```

Файл `restored.db` должен отсутствовать: существующий файл не перезаписывается.
Для создания базы нужен SQLAlchemy из зависимостей проекта. Код использует
существующие модели `app/models.py`; бот при этом не запускается.

Конфигурация JSON поддерживает:

- `bot_sender_id`: идентификатор автора ответов бота, например `user123`.
- `aliases`: проверенные соответствия старых и новых имён игроков.
- `message_aliases`: соответствия для конкретного сообщения, если одно имя
  обозначает разных игроков в разные даты.
- `ignore_message_ids`: сообщения, которые пока исключены из восстановления.
- `select_by_date`: выбор сообщения при конфликте, например
  `{"2025-08-22": 300}`; `null` исключает эту дату целиком.
- `supplemental_sessions`: вручную проверенные дополнения с датой, игроками,
  суммами, `sources` и `recorded_at_message_id`. Скрипт сам не распознаёт фото.
- `validate_snapshots`: ID выбранных сообщений `/stats`, сделанных после
  исправлений игр. Проверяются и суммы, и число игр каждого игрока.

В аудите сохраняются исходный текст, источник каждой игры, отмены, решения,
контрольные проверки и SHA-256 экспорта и конфигурации. Ненулевой баланс игры
и редактирование сообщения отмечаются предупреждениями; суммы автоматически
не исправляются. Экспорт отражает последнюю редакцию доступных сообщений и
не содержит истории правок или текста удалённых сообщений.

Архив Telegram, базы и результаты восстановления исключены из Git.
Проверки скрипта: `python -m unittest discover -s tests -v`.

Telegram-бот для учёта результатов покерных игр. Хранит группы, игроков и результаты
в SQLite, показывает суммарный выигрыш и количество сыгранных игр.

## Команды и отчёты

- `/start` — пример отчёта и список команд.
- `/stats` — статистика текущей группы. В личных сообщениях показывает общую
  статистику всех групп; просмотр доступен всем пользователям бота.
- `/undo_last` — удаляет игру с самой поздней **датой игры** в текущей группе.
  Добавление игр задним числом не меняет порядок удаления.

Добавлять отчёты и выполнять `/undo_last` могут только **владелец и администраторы
группы**. Анонимные администраторы могут отправлять сообщения от имени своей группы.
Самого бота нужно назначить администратором: это позволяет получать отчёты в группе
и надёжно проверять права других участников через
[`getChatMember`](https://core.telegram.org/bots/api#getchatmember).

Формат отчёта:

```text
Результаты 21.11.2026:
@user1 +100
@user2 -300
Имя Фамилия +200
```

Суммы — целые числа со знаком или без. На каждого игрока должна быть ровно одна
строка; повтор имени или username, в том числе с другим регистром, отклоняет отчёт.
Пустые строки разрешены. Некорректная дата, строка или пустой отчёт не сохраняются.
На одну группу допускается одна игра в день. Для исправления последней игры удалите
её через `/undo_last` и отправьте исправленный отчёт.

Весь отчёт сохраняется одной транзакцией: при ошибке не остаются ни частичные
результаты, ни новая сессия. Username сопоставляются без учёта регистра; имена
игроков хранятся как текст. Username и обычное имя не объединяются автоматически.
Сумма результатов не обязана быть равна нулю.

## Настройки

Скопируйте `.env.example` в `.env` и задайте `BOT_TOKEN`. Существующий `.env`
перезаписывать не нужно. Локально файл загружается автоматически; переменные
окружения имеют приоритет. В Docker настройки передаются через `env_file`.

| Переменная | Назначение | Значение по умолчанию |
| --- | --- | --- |
| `BOT_TOKEN` | Токен Telegram-бота от BotFather | Обязательная |
| `DATABASE_URL` | URL SQLAlchemy для базы | `sqlite:///poker.db` |
| `PROXY_URL` | Одна строка URL прокси, включая авторизацию при необходимости | Пусто, прямое подключение |
| `TUNNEL_NETWORK` | Имя внешней Docker-сети для дополнительного Compose-файла | `tunnel` |

Прокси необязателен. Например, `PROXY_URL=http://user:password@proxy:3128`
или `PROXY_URL=socks5://proxy:1080`. Специальные символы в логине и пароле должны
быть URL-кодированы. В коде нет адресов или учётных данных конкретного прокси.

## Локальный запуск

Рекомендуется Python 3.11, как в Docker-образе. Выполняйте команды из корня проекта.

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
Copy-Item .env.example .env  # только если .env ещё не существует
python -m app.main
```

На Linux/macOS активируйте окружение командой `source .venv/bin/activate`
и используйте `cp .env.example .env` при первом запуске.

## Docker Compose

При первом запуске создайте файл базы на хосте, если его ещё нет: он монтируется
в контейнер и сохраняется между пересозданиями. Существующую базу не заменяйте.

```powershell
if (!(Test-Path poker.db)) { New-Item poker.db -ItemType File }
docker compose up -d --build
docker compose logs -f bot
```

На Linux/macOS файл можно создать через `touch poker.db`. В контейнере путь
`sqlite:///poker.db` указывает на `/app/poker.db`. При изменении `DATABASE_URL`
для SQLite также обновите путь тома в `docker-compose.yaml`.

### Сеть туннеля из другого Compose-проекта

Дополнительный файл `docker-compose.tunnel.yaml` подключает бота к уже существующей
внешней сети. Узнайте фактическое имя сети проекта с туннелем (`docker network ls`)
и укажите его в `.env`, например:

```dotenv
TUNNEL_NETWORK=other-project_default
PROXY_URL=http://tunnel-proxy:3128
```

Здесь `tunnel-proxy` — имя или сетевой alias контейнера прокси в общей сети,
а `3128` — порт внутри контейнера. Замените их значениями вашего проекта.
Контейнер с туннелем запускается и управляется своим Compose-проектом.

```sh
docker compose -f docker-compose.yaml -f docker-compose.tunnel.yaml up -d --build
```

Подключение к сети само по себе не направляет трафик через VPN. Этот вариант
подходит, если туннель предоставляет HTTP/SOCKS-прокси; его адрес задаётся
через `PROXY_URL`. Для туннеля с общим сетевым пространством потребуется отдельная
настройка `network_mode` под конкретный контейнер.
Подробнее: [внешние сети Compose](https://docs.docker.com/compose/how-tos/networking/#use-an-existing-external-network).

## База данных

Таблицы создаются при запуске. Для существующей базы также добавляется уникальный
индекс `(session_id, player_id)`, запрещающий два результата одного игрока в игре.
Если в старых данных уже есть такие повторы, запуск завершится с понятной ошибкой:
перед запуском нужно проверить и исправить их вручную. Бот не удаляет и не суммирует
старые результаты автоматически. Найти повторы можно запросом:

```sql
SELECT session_id, player_id, COUNT(*)
FROM player_results
GROUP BY session_id, player_id
HAVING COUNT(*) > 1;
```

Перед ручным изменением данных сохраните копию `poker.db` при остановленном боте.
Файлы базы и `.env` исключены из Git. Статистика рассчитывается SQL-агрегацией:
один запрос на команду независимо от количества игроков.

## Проверки

После установки зависимостей:

```sh
python -m unittest discover -s tests -v
```

Проверки используют отдельные базы SQLite в памяти и подменяют Telegram API;
рабочая база и реальные сообщения не затрагиваются.
